# 优优电商 OMS 高保真原型

本项目用于承载优优业务中台 OMS 与 eBay 客服高保真原型。当前包含全局壳层、全渠道订单及应用内详情页签、eBay订单，以及订单处理、订单标发、订单规则、三方仓出库单、物流下单、物流渠道管理、三方仓库存和三方仓库龄的可交互评审原型；其余叶子菜单仍为占位页。新模块的候选规则与生产接口边界见对应 PRD，不能因原型可操作就视为业务已确认。

## 原型标注

需要标注的元素使用 `v-prototype` 绑定结构化说明。标注不是页面旁注，而是面向研发和测试的“页面逻辑执行卡”：应能从页面节点直接定位到触发条件、系统动作、结果、异常和验收口径。

```vue
<ElButton
  v-prototype="{
    id: 'oms.order.review.submit',
    标题: '提交审核',
    说明: '提交订单进入审核流程。',
    事实等级: '待确认',
    prd引用: ['PRD/订单处理功能PRD.md#op-02待审核处理'],
    前置条件: ['订单已完成必要字段校验。'],
    触发方式: ['点击提交审核。'],
    系统动作: ['写入审核轮次并执行审核规则。'],
    成功结果: ['订单进入待推单。'],
    异常处理: ['命中拦截规则时保留原因并停留在当前状态。'],
    数据来源: ['订单字段、SKU 映射和库存能力。'],
    权限与审计: ['记录操作者、时间、前后状态和决策摘要。'],
    验收要点: ['覆盖成功、拦截、重复提交和权限不足。'],
  }"
>
  提交审核
</ElButton>
```

顶部工具栏点击“原型标注”后，页面显示彩色编号，右侧同时打开非模态索引。索引支持全部、页面、字段、交互、规则、待确认分类，以及说明搜索、详情展开和页面定位。点击编号定位说明，点击说明标题定位页面；同一稳定 ID 在表格多行复用时只保留一个索引条目。开关模式均不拦截业务点击、输入、悬停或快捷键，只有独立编号按钮响应标注操作。页面重构时应保持 `id` 稳定，`prd引用` 使用完整项目内文档路径和标题锚点。详细规则以完整项目资料中的《原型标注交互规范》为准；该权威资料未随独立原型源码仓库发布。

可选字段的使用口径：

- `分类`：页面、字段、交互、规则或待确认；与事实等级、评审状态分开管理。
- `前置条件`：研发实现或测试操作前必须满足的状态、权限和数据条件。
- `触发方式`：用户动作、系统事件或时间条件。
- `系统动作`：前端交互、接口/任务、状态写入和路由行为。
- `成功结果`：用户可观察结果及业务对象最终变化。
- `异常处理`：失败、重复、缺失、未知枚举和人工核查路径。
- `数据来源`：页面字段对应的平台、OMS、仓库或本地投影来源。
- `权限与审计`：角色、数据范围、敏感数据和操作留痕要求。
- `验收要点`：研发自测和测试用例应覆盖的最小场景集合。

## 2026-09-23 三方仓库龄原型

入口：OMS → 仓配管理 → 三方仓库龄。路由：`/oms/warehouse-delivery/inventory-aging`。按 PRD V0.5 实现分段汇总、仓库 SKU 主行展开批次明细、组合筛选、分页、刷新列表、XLSX 导出及标注。使用 80 条本地虚构快照明细，默认最近日期 2026-09-23 的 75 条来源明细组成 62 条 SKU 主行或 62 组分段汇总；两视图使用同一份来源明细，不重新计算库龄或写入当前库存。

前轮用户确认 SKU 主行展开多批次及三处提示删除，本轮追加确认子表“在库数量（良品）”“在库数量（不良品）”两列并删除分段汇总数据说明；默认折叠、主行分页勾选及页面与导出联动仍为实现方案，尚非逐项确认的业务决定。日期默认当前查询范围最近有数据的一天，显式选择无数据日期不跨日补齐。批次明细按快照日期、组织、服务商、账号、仓库、来源客户、仓库 SKU、质量及单位隔离；展开保留每条来源批次，不按批次号合并，不新增主行总数量或平均库龄。子明细常驻入库委托单号，“扩展列”开关显示上架时间和失效日期。

良品／不良品两列只投影同一条来源 `on_hand_qty`，原型虚构样例按已明确质量落入对应列，另一列为空，不补 0、不按总量反算、不合并来源行。质量未知、缺失或映射未核验时两列均为空，原值留技术追溯；不能把 4PX `E/R/B` 默认均归为不良品，生产映射仍待联调。

筛选先作用于来源明细，再组成主行；分页和勾选按主行，导出包含所选主行下全部匹配子明细，XLSX 保持平铺批次行和对应质量数量列。导出确认展示视图、日期、范围及最终导出条数，并固定本次数据。页面已移除顶部虚构演示数据文字、整条采集失败提示、两视图底部来源说明及数据说明列，导出同步删除数据提示列；底层校验与汇总阻断仍生效，不新增替代提示。数据性质与业务规则继续保留在资料、标注及导出中，漏采不补历史的规则不变。分段规则、缺失值处理及未提供单位时整组暂停汇总仍为待评审演示提案。

本地预览：[三方仓库龄](http://localhost:5173/#/oms/warehouse-delivery/inventory-aging)。本轮纳入公开预览发布，真实 API、每日采集任务、服务端权限及审计均未接入。实际验证情况与未实现范围见[三方仓库龄原型验收记录](三方仓库龄原型验收记录.md)。
